# Auto-hiding scrollbar

The desktop thumb retains its 10px width, dark background, rounded 1.5px accent outline, transparent rail, and brighter hover/drag border colors. It starts invisible, fades in over 180ms on scrolling or entry into the rightmost 24px, waits 1200ms after activity, and fades out over 360ms. Width never animates. Reduced-motion preferences remove the fade.

A lightweight visual control is used because Chrome did not reliably repaint native scrollbar colors driven by an animated inherited property, even when computed styles changed. This limitation was caught with rendered-pixel tests. The final control fades through ordinary CSS opacity. Its size and position reflect the native document's viewport/scrollHeight ratio and clamped scrollY. There is no progress line, alternate scroll container, wheel interception, animation library, or replacement scroll engine. Existing Lenis, pinned scenes, anchors and navigation remain unchanged. Native styling is retained as the fallback; native scrollbar styling varies by engine ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/::-webkit-scrollbar)).

Dragging uses pointer capture and maps pointer movement directly to native window.scrollTo with instant behavior. Focusing the handle uses the existing smooth-scroll focus handler to interrupt any pending Lenis interpolation. Stationary dragging suppresses the idle timer; release/cancellation restores idle behavior and releases pointer focus. Keyboard users can focus the labeled vertical scrollbar with its page percentage and main-content association. Normal browser scrolling keys remain functional, and visible keyboard focus prevents hiding. No per-frame React rerenders occur. Measurements use an input-driven animation frame, resize events and a body ResizeObserver; timers, capture and listeners are cleaned up on teardown.

Touch-capable devices, small screens and forced-colors mode retain system scrollbars. JavaScript-disabled pages retain native scrollbar styling. The custom control is hidden in these fallback modes.

## Verification

Run `PLAYWRIGHT_MODULE=/path/to/playwright node tests/scrollbar.browser.mjs [baseURL]` with installed Chrome. The suite covers initial invisibility, sustained near-edge hover, actual mouse dragging and stationary capture, idle delay/intermediate fade/completion, immediate reveal on resumed scrolling, unchanged layout width, accurate thumb position and accessible percentage, dark interior and hover/pressed colors, absence of progress overlays, anchors, history/reload, resize, reduced motion, forced colors, keyboard scrolling while focused, mobile/touch desktops, a case-study route and JavaScript-disabled native fallback.

TypeScript, ESLint, all 26 unit tests, production build and GitHub Pages static export pass. The browser suite passes against development and exported production sites. Existing cinematic tests check storytelling, gallery controls, focus restoration and reduced-motion fallbacks. A separate screenshot pixel check confirms zero visible thumb pixels initially and after idle, visible outline pixels during scrolling, and a usable JavaScript-disabled native fallback.

Chrome was available for execution. Safari access was unavailable through browser permissions; Firefox and Edge were not installed. These browsers were not directly tested and still need manual visual verification. Automated wheel tests do not certify physical trackpad hardware.
